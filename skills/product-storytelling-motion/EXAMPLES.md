# Worked example: Agent as a Service

## Transformation

A teammate who receives an Agent link goes from reconstructing someone else's
context to continuing the work immediately, without changing the publisher's
original session.

## Filmstrip

### Frame 1 — Start with the work

- **Claim:** Skip the briefing. Start the work.
- **Product object:** the real Agent-ID input and share link.
- **State change:** a shared ID resolves into a named Agent with a ready prompt.
- **Hold:** the input remains usable throughout the hero.

### Frame 2 — The context is already there

- **Claim:** Your first message can be the real task.
- **Product object:** one recognizable conversation surface.
- **State change:** earlier context condenses behind the Agent header; a new,
  concrete task enters and receives a context-aware answer.
- **Example task:** “Turn this research into three decisions.”
- **Avoid:** floating context cards, data particles, or architecture labels.

### Frame 3 — Send one link

- **Claim:** Hand over the Agent, not another brief.
- **Product object:** the same Agent share page.
- **State change:** the URL is pasted into Web, Codex, and Claude Code surfaces;
  each surface reaches the same ready state.
- **Hold:** show the exact next action in every destination.

### Frame 4 — Continue independently

- **Claim:** Share the capability. Keep every conversation private.
- **Product object:** two full conversation surfaces using the same Agent.
- **State change:** each person asks a different task and receives a different
  output; the publisher's source remains visibly unchanged.
- **Avoid:** explaining forks, snapshots, routing, or IDs in the headline.

### Frame 5 — Trust and action

- **Concern:** Will my original work or another user's conversation change?
- **Answer:** show a source-session checksum/state before and after two uses,
  translated into plain language.
- **CTA:** paste an Agent ID or open the shared Agent.

## Motion map

| Range | Copy | Product action |
| --- | --- | --- |
| 0–18% | Frame 2 enters | conversation surface settles |
| 18–34% | copy holds | task sends and answer appears |
| 34–42% | copy exits | share URL becomes the inherited object |
| 42–58% | Frame 3 holds | URL moves through three destinations |
| 58–66% | copy exits | two conversation surfaces separate |
| 66–88% | Frame 4 holds | independent outputs complete |
| 88–100% | story releases | normal-flow trust section appears |

Each boundary includes a short quiet gap. Large headlines never crossfade over
one another.
